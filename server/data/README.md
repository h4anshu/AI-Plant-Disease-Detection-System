# Data files for the official warnings (docs/FIELD_ALERTS.md, section 7)

- `lgd_districts.json`: `[[LGD code, district, state], ...]`, **787 districts**. The first 765 are the India Data Portal "District LGD Codes" (https://ckandev.indiadataportal.com/dataset/lgd-codes, a copy of the Local Government Directory, https://lgdirectory.gov.in, **Open Data Commons Attribution License, ODC-By**: attribution required, given here and in docs/FIELD_ALERTS.md; that file is dated Oct 2023 and the portal has not updated it since). The 22 newer ones (codes 766 and up: the Rajasthan districts created in 2023, Maihar, Pandhurna, Hansi and others) come from the Local Government Directory's daily snapshot mirrored at https://ramseraph.github.io/opendata/lgd/ (dataset `districts`, observed 27 Oct 2026; the mirror states no licence of its own, the data is the directory's: check before any commercial use). Codes never change and SACHET uses them; **names do change** (Cuttack is "Kataka" in the directory now), so a code that is already in the file keeps the name and state it has, because IMD's names were paired with those spellings.
- `imd_lgd.json`: IMD `india_districts` (state, district) -> LGD code. Generated; do not edit. 729 of IMD's 741 districts are mapped; the rest are in Pakistan-administered Kashmir (2) or not in IMD's layer under any similar name. **A district created after IMD's layer was drawn (Phalodi, Deeg, Beawar and the other new Rajasthan ones) is in the LGD table, but a field there is still found by IMD under its old district, so a SACHET alert addressed to the new district's code will not reach it until IMD updates its layer.**
- `imd_lgd_aliases.json`: the hand-written part of that table (IMD spellings the script cannot pair). Edit this, then run the build; it prints every similar-name guess and every district left over.
- `official_links.json`: the official pages shown on the news card (docs/FIELD_ALERTS.md, section 10). `states` is for a state's own agriculture pages, to be filled in by hand.
- `alert_review.json`: the reviewer's verdicts on the alert rules (`npm run alerts-review -- --apply`, docs/FIELD_ALERTS.md, section 13). Written by the script, not by hand.

## Refreshing the district list
1. Get the newest `districts` Parquet file from https://ramseraph.github.io/opendata/lgd/data/metadata.json (the `districts` entry, `daily.file.url`) and turn it into `[[code, name, state], ...]` JSON, for example with `pyarrow` in a throwaway environment (not the project's): `[[int(r['district_code']), r['district_name'], r['state_name']] for r in pq.read_table(file).to_pylist()]`.
2. `cd server && node scripts/merge_lgd.js <that.json>` adds the new codes (state spelled the way the file already writes it, capitals tidied), keeps the names it has, keeps codes that left the list, trims stray spaces, and prints what it did.
3. `node scripts/build_district_map.js --lgd data/lgd_districts.json` rebuilds `imd_lgd.json` from IMD's current layer and prints the similar-name guesses (check each) and the districts left over. It refuses to write if the list has under 700 rows.
4. `npm test`: `tests/lgdMerge.test.js` checks the counts, that every IMD district points at an existing code and that the spellings the news and price cards match on are intact.
